# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
The detection engine scores every feature vector for the likelihood that observed behaviour precedes or constitutes a disruption. Five complementary models score in parallel; a fusion layer combines them into a composite score with per-model contributions and SHAP explanations, published to `ml.detections`. Baseline construction, training pipelines and model governance are in TS-06; severity and suppression decisions are in TS-07.
# 2. Model Portfolio
| Model | Anomaly class targeted | Cadence | Input | Output | Latency target |
|---|---|---|---|---|---|
| M1 LSTM Autoencoder | Gradual degradation, time-correlated drift (leaks, slow saturation) | Every 5m vector | Sequence of last 24 × 5m vectors (2 h) | Reconstruction error per feature | ~8 ms CPU / ~2 ms GPU |
| M2 Isolation Forest | Point anomalies, sudden shifts, novel values | Every 1m and 5m vector | Single vector + baseline deltas | Normalised path-length score | ~1 ms |
| M3 Graph Neural Network | Topology anomalies, cascade onset, lateral movement | Every 30 s (full graph) | Service graph snapshot | Node and edge anomaly scores | ~50 ms per graph |
| M4 Transformer Sequence | Known multi-step precursor chains | Every 1m per entity cluster | 2 h token sequence of discretised events | P(failure mode k within horizon) | ~15 ms |
| M5 Statistical Process Control | Threshold crossings, spikes, sustained drift | Every 1m vector (in Flink fast path) | 24 curated metrics per class | Rule violations + severity | < 0.5 ms |
# 3. Key Design Decisions
| Decision | Rationale |
|---|---|
| Ensemble of heterogeneous models | Different anomaly classes have different signatures; diversity prevents correlated misses |
| Parallel, independent scoring | Per-request latency bounded by slowest model, not the sum |
| SPC runs inside Flink as well as in the service | Detection continues in degraded mode if the inference service is down |
| GNN runs on a schedule, not per event | Graph scoring is O(edges); 30 s cadence balances freshness and cost |
| Fusion weights learned from historical precision per domain | Models are trusted where they have been right |
| SHAP on every composite score | Explainability requirement (TS01-NFR-009) |
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS05-NFR-001 | Per-vector inference (M1, M2, M4, M5 + fusion) ≤ 50 ms P99 |
| TS05-NFR-002 | Graph scoring cycle completes within 30 s for ≤ 50k nodes / 500k edges |
| TS05-NFR-003 | Inference service horizontally scalable 3–20 replicas, stateless |
| TS05-NFR-004 | SHAP computation adds ≤ 20 ms P99 (TreeSHAP for M2; precomputed DeepSHAP background for M1) |
| TS05-NFR-005 | Ensemble weighted F1 ≥ 0.85 on held-out validation at Month 12 |
# PART B — LOW-LEVEL SPECIFICATION
# 5. Model Specifications
## 5.1 M1 — LSTM Autoencoder
| Item | Specification |
|---|---|
| Granularity | One model per entity class (shared weights), entity embedding (dim 16) concatenated to input |
| Input | Tensor [T=24, F_class] of 5m vectors, z-scored with class population baseline; NaN → 0 with mask channel |
| Encoder | LSTM(256) → LSTM(128) → LSTM(64), return_sequences on first two; dropout 0.2 |
| Bottleneck | Dense(32), tanh |
| Decoder | RepeatVector(24) → LSTM(64) → LSTM(128) → LSTM(256) → TimeDistributed(Dense(F_class)) |
| Loss | Masked MSE per feature dimension |
| Training | Adam lr 1e-3 (cosine decay), batch 256, ≤ 50 epochs, early stopping patience 5 on validation loss; trained only on windows without incident labels |
| Raw score | Mean reconstruction error over last 3 timesteps, weighted toward latest (0.2, 0.3, 0.5) |
| Per-feature attribution | Per-feature reconstruction error share (native explanation) |
| Activation | Disabled in Bootstrap-0; enabled from Bootstrap-1 (TS-06) |
| Known limitation handling | Absorbs instantaneous spikes — covered by M2/M5 |
## 5.2 M2 — Isolation Forest
| Item | Specification |
|---|---|
| Granularity | One model per entity class and window (1m, 5m) |
| Input | Current vector ⊕ behavioural deltas (`beh.z_individual`, `beh.z_peer`) |
| Hyperparameters | `n_estimators`=200, `max_samples`=256, `max_features`=1.0 with per-tree random feature subsample of √F, `contamination`='auto' |
| Raw score | sklearn `score_samples` negated (higher = more anomalous) |
| Attribution | TreeSHAP over the forest (path-length contribution) |
| Crowding mitigation | Train on 14-day sample stratified by hour bucket; add M2 variant on peer-group deltas only, max of two scores used |
## 5.3 M3 — Graph Neural Network
| Item | Specification |
|---|---|
| Graph | Nodes = resolved entities (services, hosts, DBs, users, network devices); edges = observed interactions in last 5m plus CMDB dependencies (typed) |
| Node features | Latest 5m vector subset (32 dims) + class one-hot + tier |
| Edge features | calls/s, error ratio, p95 latency, edge type (observed / declared / both), edge age |
| Architecture | 4 × GATv2 layers (hidden 128, 4 heads, residual, LayerNorm), edge-feature attention |
| Objectives | (a) node feature reconstruction (self-supervised); (b) link-existence prediction (contrastive negative sampling); (c) supervised head for incident propagation where labels exist |
| Scores | Node score = 0.5·reconstruction + 0.5·unexpected-edge aggregate; edge score = 1 − P(edge | normal graph) for new edges, \|Δweight\| z for existing |
| Cadence | Snapshot every 30 s from `gr:*` keys (TS-04) for affected subgraphs; full graph every 5 min |
| Outputs used downstream | Node scores (fusion), top anomalous edges and 2-hop propagation path (root-cause candidates, blast radius in TS-07) |
| Dependency | CMDB quality; if declared-edge coverage < 70% for a service, its GNN weight is capped at 0.1 |
## 5.4 M4 — Transformer Sequence Model
| Item | Specification |
|---|---|
| Tokenisation | Events and threshold crossings discretised into tokens: `<entity_class>|<signal>|<bucket>` (e.g. `db|pool_wait|p95_high`); vocabulary ≈ 20k; 1m resolution |
| Context | 2 h sliding window, max 512 tokens per entity neighbourhood (entity + 1-hop dependencies) |
| Architecture | Encoder-only, 6 layers, d_model 256, 8 heads, FFN 1024, learned time-delta embeddings, [CLS] pooling |
| Heads | Multi-label classification over K known failure modes (from incident taxonomy) for horizons 15/30/60 min; plus "no known pattern" |
| Training data | ≥ 18 months incident history (min 12 months to enable); positive sequences = 2 h preceding confirmed incidents; negatives = random windows without incidents within 6 h |
| Imbalance | Focal loss (γ = 2), class weights capped at 50 |
| Raw score | max_k P(k, 30 min) ; mode k* and horizon reported |
| Attribution | Attention rollout + integrated gradients over tokens → top 5 precursor events |
| Limitation handling | Novel modes produce low scores by design; M1/M2/M3 cover novelty |
## 5.5 M5 — Statistical Process Control
| Item | Specification |
|---|---|
| Metrics | 24 curated metrics per entity class (registry flag `curated_for_spc`) |
| Shewhart | X̄ chart; centre = contextual baseline mean; limits ±3σ; Western Electric rules 1–4 |
| CUSUM | Tabular, k = 0.5σ, h = 5σ, upper and lower |
| Limits refresh | Hourly from 7-day rolling window per (entity, hour-of-week) context |
| Raw score | max over metrics of rule severity: rule1 = 1.0, CUSUM h-crossing = 0.9, rule2 = 0.7, rule3/4 = 0.5 |
| Deployment guard | If `ctx.deployment_active`, limits widened to ±4σ for 30 min (relaxed baseline, TS-06) |
# 6. Score Normalisation and Fusion
## 6.1 Normalisation
Each model's raw score r is mapped to [0, 1] with a calibrated sigmoid using that model's trailing 30-day score distribution for the entity class:
```
s = 1 / (1 + exp(-a * (r - q99) / (q999 - q99)))      # a = 4.0 default
```
so that the class's 99th percentile maps to 0.5 and the 99.9th percentile to ≈ 0.98. Parameters (q99, q999) are recalculated daily by TS-06 and versioned with the model.
## 6.2 Fusion algorithm
```
inputs: for each model m in active_models(entity):
          s_m  ∈ [0,1]   normalised score
          c_m  ∈ [0,1]   model confidence
          d    = event domain of entity
          P_md = historical precision of m on domain d (trailing 90 days, Laplace-smoothed)
w_m  = P_md / Σ_j P_jd
s'_m = s_m                       if c_m ≥ 0.6
       s_m * (c_m / 0.6)         if c_m < 0.6            # confidence discounting
S    = Σ w_m s'_m / Σ w_m
n_hi = |{ m : s'_m > 0.7 }|
if n_hi ≥ 3: S = min(1.0, S * 1.15)                     # consensus boost
if baseline_maturity == Bootstrap-1: S = S / 2.0        # threshold elevation 2x (TS-06)
if baseline_maturity == Bootstrap-2: S = S / 1.5        # threshold elevation 1.5x
emit detection if S ≥ emit_threshold (default 0.35)      # lower than incident thresholds; TS-07 decides
```
## 6.3 Model confidence definitions
| Model | Confidence c_m |
|---|---|
| M1 | 1 − (masked feature fraction) × (1 − baseline maturity factor) |
| M2 | Agreement across trees: 1 − normalised std of per-tree path lengths |
| M3 | min(1, declared-edge coverage / 0.7) × node degree reliability |
| M4 | Max class probability margin over second class; 0 if corpus below minimum |
| M5 | 1.0 when ≥ 7 days of limits; else days/7 |
# 7. Detection Message (`ml.detections`)
```
record Detection {
  string detection_id;              // UUIDv7
  string feature_vector_id;
  string entity_id; string entity_class; string domain;
  long   ts_ms;                     // window_end of triggering vector
  float  composite_score;
  string baseline_maturity;
  array<ModelScore> models;         // {model, version, raw, normalised, confidence, weight, contribution}
  array<FeatureContribution> shap;  // top 10 {feature, value, baseline, shap_value}
  array<PrecursorEvent> precursors; // from M4: {token, ts_ms, attribution}
  FailureMode predicted_mode;       // from M4: {mode_id, probability, horizon_min} | null
  array<GraphFinding> graph;        // from M3: {path:[entity_ids], edge_scores, node_scores}
  map<string> context;              // deployment_active, maintenance_active, change_id
  boolean degraded;                 // true if any model unavailable
  string  explanation_text;         // templated one-line rationale for analysts
}
```
Example `explanation_text`: "error_rate.5m 7.2σ above Tuesday 10:00 baseline; LSTM reconstruction error rising for 40 min; Transformer matches 'connection-pool exhaustion' pattern (p=0.71, 30 min)."
# 8. Inference Service
| Item | Specification |
|---|---|
| Runtime | Python 3.12, ONNX Runtime (M1, M4, M2 via skl2onnx), PyTorch Geometric for M3 in a separate `gnn-scorer` deployment |
| Interface | Kafka consumer on `features.vectors` (group `cg-inference`), micro-batches of ≤ 256 vectors or 50 ms |
| Concurrency | Models executed concurrently per micro-batch (thread pool per model) |
| Sequence fetch | `GetSequence` batch call to Feature Service (TS-04) for M1/M4 inputs |
| Model loading | Pulls approved versions from Model Registry on start and on `control.config` event; hot-swap with double-buffering; readiness false during load |
| Shadow mode | Candidate models (TS-06) score in parallel; results to `ml.detections.shadow` only |
| Resources | 8 vCPU / 16 GiB per replica; optional GPU (T4/L4 class) for M1/M4 |
| Idempotency | Detection keyed by `feature_vector_id + model_bundle_version` |

# 10. Failure Modes
| Failure | Handling |
|---|---|
| One model fails to load / errors | Excluded from fusion; weights renormalised; `degraded=true`; P3 platform incident |
| Inference service fully down | SPC fast path in Flink emits detections with `models=[M5]`, `degraded=true` |
| Feature sequence missing | M1/M4 skip entity (confidence 0); others proceed |
| GNN cycle overrun | Skip next cycle, score affected subgraphs only; alert if 3 consecutive overruns |
| Score distribution shift after model promotion | Auto-rollback triggers in TS-06 (FP rate > 2× within 6 h) |
# 11. Self-Observability
| Metric | Alert |
|---|---|

# 12. Security Controls
| ID | Control |
|---|---|
| TS05-SEC-001 | Model artefacts signed at registration; signature verified before load |
| TS05-SEC-002 | Inference service has read-only access to Feature Service and Registry; no write to any store except Kafka detections |
