# 1. Purpose
This index governs a set of 17 component technical specifications (TS-01 to TS-17) that decompose the white paper "Proactive Infrastructure Disruption Detection & Automated Incident Response" into buildable units. The white paper describes what the solution does and why; the specifications describe how each component is built, configured, integrated, operated and accepted.
Overlapping white paper sections have been merged by system component, so that each component has exactly one authoritative specification. Where a white paper section contributes to more than one component, the split is shown in Section 3.

# 5. Conventions
## 5.1 Requirement identifiers
Requirements use the form `TSnn-TYPE-nnn`, for example `TS05-FR-012`. Types: **FR** functional, **NFR** non-functional, **SEC** security, **OPS** operational, **AC** acceptance criterion. Each AC references the requirement(s) it verifies. Keywords MUST, SHOULD and MAY carry their RFC 2119 meanings.
## 5.2 Units and formats
- Time: UTC, ISO 8601 with millisecond precision (`2026-10-14T09:15:30.125Z`). Durations in ISO 8601 (`PT5M`) in configuration, seconds in metrics.
- Scores: all anomaly, confidence and similarity scores are normalised floats in the closed range [0.0, 1.0].
- Sizes: binary units (MiB, GiB) for memory and storage; events per second (eps) for throughput.
- Identifiers: UUIDv7 for events, incidents and actions (time-ordered); CMDB CI identifiers retained as issued by the CMDB.
- Configuration: YAML, versioned in Git, delivered via GitOps (TS-11). No component reads configuration from mutable local files.

# 7. Change Control for this Specification Set
- Each specification is versioned independently; a change to a shared identifier, vocabulary or schema in this index requires review by the owners of every dependent specification.
- Parameter values quoted from the white paper (thresholds, SLAs, targets) are marked as **baseline defaults**. Changes to defaults are configuration changes, not specification changes, provided they stay within the documented allowed range.
- Architecture Review Board sign-off is required before a specification moves from Draft to Approved.
