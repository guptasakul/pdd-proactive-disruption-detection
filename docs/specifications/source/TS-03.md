# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
This component turns heterogeneous raw telemetry from `raw.<domain>` into a single, ordered, deduplicated, ECS-normalised and entity-resolved stream on `norm.events`. It covers pipeline stages 1 (Log Aggregation) and 2 (Schema Normalisation) and the Kafka backbone used by all later stages. Feature extraction and the Feature Store (stages 3–4) are in TS-04.
# 2. Component Decomposition
| Sub-component | Technology | Responsibility |
|---|---|---|
| Kafka backbone | Apache Kafka ≥ 3.7 (KRaft), Cruise Control | Durable transport, partitioning, retention, tiered storage |
| Schema Registry | Confluent Schema Registry (or Apicurio) | Avro/Protobuf schema enforcement and evolution |
| `ingest-aggregate` job | Apache Flink ≥ 1.19 | Fan-in from `raw.*`, deduplication, rate limiting, repartition by entity hint |
| `ingest-normalise` job | Apache Flink | ECS mapping, timestamp/severity normalisation, PII pseudonymisation, entity resolution, enrichment |
| Reference data broadcaster | Flink broadcast state fed from CMDB, change calendar and TI topics | Distribute CMDB mappings, maintenance windows, deployments, TI indicators to all task slots |
| Mapping repository | Git + CI | Versioned per-source ECS mapping specifications |
| Dead-letter handler | Kafka topic + triage UI | Quarantine and replay of rejected events |
# 3. Key Design Decisions
| Decision | Rationale | Alternatives rejected |
|---|---|---|
| Separate topic per domain on ingest | Independent retention, quotas and consumer scaling per domain; noisy domains cannot starve others | Single raw topic (blast radius); topic per source (thousands of topics) |
| Repartition by `entity_id` after resolution | Guarantees per-entity ordering for windowed features and LSTM sequences | Partition by source host (entity spread across partitions) |
| Event-time processing with bounded watermarks | Correct windows despite network delay; late data handled explicitly | Processing time (wrong windows during backlog) |
| Broadcast state for reference data | Sub-millisecond lookups without per-event calls to CMDB | Async I/O to CMDB (latency, CMDB load) — retained only as cache-miss fallback |
| Exactly-once via Flink checkpoints + Kafka transactions | Prevents duplicate features that would distort volumetric features | At-least-once with downstream dedup (feature skew) |
| Mapping-as-code | Reviewable, testable, versioned alongside pipeline | UI-configured parsers (unreviewable drift) |
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS03-NFR-001 | Sustain 500k eps steady, 2M eps burst for 15 min |
| TS03-NFR-002 | Stage 1+2 latency (raw produce → norm produce) ≤ 5 s P99 at steady state |
| TS03-NFR-003 | No acknowledged-event loss on single broker, single TaskManager or single AZ failure |
| TS03-NFR-004 | Entity resolution success ≥ 95% of events (unresolved events still flow, tagged) |
| TS03-NFR-005 | Checkpoint duration ≤ 30 s P95; checkpoint interval 60 s |

# 7. Stage 1 — Aggregation Logic
## 7.1 Flow
```
for each record r from raw.<domain>:
    validate envelope + required resource attributes        -> else DLQ(reason=missing_attr)
    if source_id not approved                                -> DLQ(reason=unknown_source)
    if token_bucket[source_id].try_consume(1) == false       -> metric dropped_rate_limited; drop
    h = xxh3_128(source_id || floor(ts_ms) || canonical(body))
    if dedup_state.contains(h) within 60s                    -> metric duplicate; drop
    dedup_state.put(h, ttl=60s)
    key = entity_hint(r)   # service.name | host.name | k8s pod uid | device ip
    emit(keyBy(key), r)
```
## 7.2 Parameters
| Parameter | Default | Range | Note |
|---|---|---|---|
| `dedup.window` | PT60S | PT10S–PT5M | RocksDB state with TTL |
| `dedup.state.ttl.cleanup` | incremental, 1000 entries/record | — | |
| `ratelimit.default_eps` | from descriptor | — | Token bucket per source, burst = 2× rate for 30 s |
| `watermark.max_out_of_orderness` | PT10S | PT2S–PT60S | Per-source override allowed |
| `allowed_lateness` | PT2M | ≤ PT10M | Late events beyond this go to side output `late` and are still normalised but excluded from closed windows |
| `parallelism` | 48 | 8–256 | Autoscaled (TS-12) |
| `checkpoint.interval` | PT60S | PT30S–PT5M | Unaligned checkpoints enabled under backpressure |
# 8. Stage 2 — Normalisation Logic
## 8.1 ECS mapping specification
```
# mappings/app.apigw/v3.yaml
source_type: app.apigw
version: 3
parse: { format: json }
fields:
  "@timestamp":              { from: ts, convert: iso8601_to_epoch_ms }
  http.response.status_code: { from: status, convert: int }
  url.path_template:         { from: path, transform: path_templater }   # /orders/123 -> /orders/{id}
  event.duration_us:         { from: latency_ms, convert: ms_to_us }
  source.ip:                 { from: client_ip }
  user.id_pseudo:            { from: consumer_id, transform: pseudonymise }
  service.name:              { from: upstream_service }
derive:
  event.outcome:  "status < 400 ? 'success' : 'failure'"
  event.category: ["web"]
  event.severity: "status >= 500 ? 60 : (status >= 400 ? 30 : 10)"
tests: tests/app.apigw/*.json      # golden input/output pairs executed in CI
```
Mapping rules: every mapping MUST include golden tests; CI rejects a mapping whose tests fail or whose output fails `norm.events` schema validation. Mapping versions are deployed with the job and recorded in `labels.mapping_version`.
## 8.2 Timestamp normalisation
1. Parse source timestamp per mapping; if absent use `observed_timestamp` and add `quality.flags += no_source_ts`.
2. Convert to UTC epoch ms. Timezone-less timestamps use the source descriptor's `timezone` (default UTC).
3. If |source_ts − observed_ts| > 5 s, add `clock_skew`; if skew for the source has a stable median over 1 h, apply the median correction and record `labels.skew_correction_ms`.
## 8.3 Severity normalisation (0–100)
| Source scale | Mapping to `event.severity` |
|---|---|
| Syslog 0–7 (emerg→debug) | 100, 90, 80, 70, 50, 30, 20, 10 |
| Log level FATAL/ERROR/WARN/INFO/DEBUG/TRACE | 90 / 70 / 50 / 20 / 10 / 5 |
| CVSS 0–10 | CVSS × 10 |
| Vendor 1–5 (low→critical) | 20, 40, 60, 80, 95 |
| Metrics | 0 (severity is computed by ML, not source) |
## 8.4 Entity resolution
Resolution order (first hit wins), all from broadcast state:
| Order | Key | Lookup table | Example |
|---|---|---|---|
| 1 | `k8s.pod.uid` → workload | `k8s_workload_to_ci` | pod → deployment → service CI |
| 2 | `service.name` (+ environment) | `service_name_to_ci` | `payments-api` → `cmdb_ci_service:SVC0042` |
| 3 | `host.name` (FQDN, lower-cased) | `hostname_to_ci` | |
| 4 | `host.ip` / `source.ip` (+ site) | `ip_to_ci` (interval tree, DHCP-aware TTL) | |
| 5 | Cloud resource ARN / ID | `cloud_resource_to_ci` | |
| 6 | Device serial / SNMP sysName | `device_to_ci` | |
If none hits: `entity.id = unresolved:<best_hint>`, `quality.flags += unresolved_entity`, async CMDB query (500 ms timeout, result cached 15 min). Unresolved rate per source is a data-quality KPI reported weekly to CMDB owners.
## 8.5 Reference-data broadcast
| Stream | Source | Refresh | Size estimate |
|---|---|---|---|
| CMDB CI and relationship snapshots + deltas | CMDB API → `ref.cmdb` (compacted) | Full nightly, deltas via webhook | ≤ 2 GiB state |
| Maintenance windows | Change calendar → `ref.maintenance` | On change | Small |
| Deployments / change records | CI/CD + change system → `ref.changes` | Real time | 30-day window |
| Threat-intel indicators | TAXII puller → `ref.ti` (compacted) | Hourly + on publish | ≤ 5M indicators (bloom filter + exact map) |
## 8.6 Enrichment
- **Change context:** set `context.deployment_active = true` if a deployment on the entity or its direct dependencies started in the last 30 minutes; set `context.maintenance_active` if within a scheduled window covering the entity; set `context.change_id`.
- **Threat intelligence (security and network domains only):** match `source.ip`, `destination.ip`, DNS `qname` and file hashes against TI bloom filter, then exact map; on match set `threat.indicator.matched`, `type`, `confidence`, `feed`.
- **Message templating:** log messages reduced to templates with Drain3 (similarity threshold 0.5, depth 4) so that `error.message_template` is a stable, low-cardinality feature key; variable tokens stored in `labels.params` only for application logs.
## 8.7 PII pseudonymisation
Fields listed in the source descriptor's `pii_fields` are replaced with `HMAC-SHA256(key_v, value)` truncated to 128 bits. Keys are held in KMS and rotated every 90 days with a 30-day overlap (both versions resolvable for correlation). Raw values are never written to `norm.events`. See TS-10 for policy.
# 9. Dead-Letter Handling
| Reason code | Example | Replayable |
|---|---|---|
| `missing_attr` | No `source.id` | After collector fix |
| `unknown_source` | Descriptor not approved | After approval |
| `parse_error` | Malformed JSON | After mapping fix |
| `schema_violation` | Output fails Avro validation | After mapping fix |
| `oversize` | > 1 MiB after parse | No (truncated copy logged) |
Dead-letter records carry the original bytes (base64), reason, mapping version and stack trace. A replay tool re-injects selected records into `raw.<domain>` with header `x-replay=true`; replayed events are excluded from real-time detection when older than 10 minutes but included in training data.
# 10. Failure Modes
| Failure | Detection | Handling |
|---|---|---|
| Broker loss | Under-replicated partitions | Leaders move; producers retry; Cruise Control self-heals replicas |
| TaskManager loss | Flink job restart | Restore from last checkpoint; Kafka transactions abort uncommitted output |
| Checkpoint timeouts | Checkpoint duration > 120 s | Enable unaligned checkpoints; scale out; alert |
| CMDB feed stale > 24 h | `ref.cmdb` lag metric | Continue on last snapshot; flag `cmdb_stale` on events; P3 platform incident |
| Mapping regression | DLQ rate spike for a source after deploy | Automatic rollback of mapping version via GitOps if rejection > 5% for 10 min |
| Backpressure | Consumer lag > 50k/partition (KRI) | Autoscale parallelism (TS-12); per-source rate limits protect shared capacity |
# 11. Self-Observability
| Metric | Alert threshold |
|---|---|
| `kafka_consumergroup_lag{group}` per partition | > 50,000 (KRI) |
| `ingest_dlq_rate{source_id}` | > 2% of source volume over 15 min (KRI) |
| `ingest_dedup_ratio{source_id}` | > 30% (indicates double collection) |
| `entity_resolution_rate{source_id}` | < 95% |
| `flink_checkpoint_duration_p95` | > 30 s |
| `stage12_latency_p99` | > 5 s |

# 13. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS03-AC-001 | Golden tests pass for 100% of approved mappings in CI |
