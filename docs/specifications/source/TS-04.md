# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
This component converts `norm.events` into per-entity feature vectors at 1-minute, 5-minute and 1-hour windows (stage 3), serves them with sub-5 ms latency to ML inference (stage 4, online store), and materialises them with labels for training (offline store). It also computes baseline deltas using baseline statistics published by TS-06.
# 2. Component Decomposition
| Sub-component | Technology | Responsibility |
|---|---|---|
| `feature-extract` job | Flink (event time, sliding/tumbling windows) | Compute six feature categories per entity and window |
| Graph aggregator | Flink keyed by (src_entity, dst_entity) | Edge weights for service call graph and peer entropy |
| Online store | Redis Cluster 7.x, 6–18 nodes | Latest vectors, sequence history, baseline deltas |
| Offline store | Parquet on object storage, Iceberg table format | Point-in-time-correct training data |
| Feature registry | YAML definitions in Git + generated documentation | Single definition per feature, used by stream job and training code |
| Serving API | gRPC service (stateless) | Batch fetch of vectors and sequences for inference and agents |
# 3. Key Design Decisions
| Decision | Rationale |
|---|---|
| One feature definition drives both streaming and offline computation | Prevents training/serving skew |
| Sliding windows with incremental aggregation | 1m windows slide every 15 s; 5m every 1m; 1h every 5m — fresh scores without full recomputation |
| Hash-tagged Redis keys per entity | All keys for an entity co-locate in one hash slot; multi-key reads are single-node |
| Baseline delta computed at write time | Inference reads a ready delta; avoids per-request baseline lookup |
| Iceberg offline store with event-time partitioning | Point-in-time joins with labels; time travel for reproducible training sets |
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS04-NFR-001 | Online read P99 ≤ 5 ms for a single entity vector; ≤ 10 ms for a 100-entity batch (KRI threshold 10 ms) |
| TS04-NFR-002 | Feature freshness: window close → vector in online store ≤ 5 s P99 |
| TS04-NFR-003 | Online store availability ≥ 99.9% |
| TS04-NFR-004 | Offline materialisation complete for day D by D+1 02:00 UTC |
| TS04-NFR-005 | Training/serving parity: ≤ 0.1% of features differ beyond 1e-6 relative error on reconciliation |
# PART B — LOW-LEVEL SPECIFICATION
# 5. Feature Catalogue
Feature names follow `<category>.<name>.<window>`. The catalogue below is the baseline set (≈ 140 features per entity after window expansion); entity classes subscribe to subsets via the registry.
## 5.1 Volumetric
| Feature | Windows | Definition | Classes |
|---|---|---|---|
| `vol.event_count` | 1m 5m 1h | Count of events for entity | All |
| `vol.request_rate` | 1m 5m | Requests/s (http, rpc, db) | service, apigw, db |
| `vol.error_rate` | 1m 5m 1h | Failure-outcome events / total events | service, apigw, db |
| `vol.bytes_out`, `vol.bytes_in` | 1m 5m | Sum of bytes | host, network device |
| `vol.conn_count`, `vol.new_conn_rate` | 1m 5m | Active connections; new connections/s | host, lb, db |
| `vol.log_error_count` | 1m 5m | Count of log events with severity ≥ 70 | All |
## 5.2 Statistical
| Feature | Windows | Definition |
|---|---|---|
| `stat.latency_mean`, `stat.latency_std` | 5m 1h | Welford online mean/variance of duration |
| `stat.latency_p50/p95/p99` | 5m 1h | t-digest (compression 100) quantiles |
| `stat.interarrival_mean`, `stat.interarrival_cv` | 5m | Mean and coefficient of variation of inter-arrival time |
| `stat.metric_<name>_mean/max/slope` | 5m 1h | Per curated metric (CPU, memory, queue depth, lag…); slope = OLS over window |
## 5.3 Relational
| Feature | Windows | Definition |
|---|---|---|
| `rel.out_degree`, `rel.in_degree` | 5m 1h | Distinct callees / callers |
| `rel.peer_entropy` | 5m 1h | Shannon entropy of traffic share across peers: −Σ pᵢ log₂ pᵢ |
| `rel.new_peer_ratio` | 1h | Peers not seen in prior 7 days / total peers |
| `rel.fanout_change` | 5m | (out_degree₅ₘ − out_degree mean over 1h) / max(1, std) |
| `rel.edge_weight[dst]` | 1m 5m | Calls and error ratio per edge (written to graph keys, not the dense vector) |
## 5.4 Temporal
| Feature | Definition |
|---|---|
| `tmp.hour_sin`, `tmp.hour_cos` | Cyclic encoding of hour of day (local business time zone of entity) |
| `tmp.dow_sin`, `tmp.dow_cos` | Cyclic encoding of day of week |
| `tmp.days_since_seen` | Days since entity last observed (new-entity indicator) |
| `tmp.change_velocity` | Count of change records on entity in 24 h |
| `tmp.mins_since_last_anomaly` | From `ml.detections` feedback (capped at 10,080) |
## 5.5 Contextual (point in time)
| Feature | Definition |
|---|---|
| `ctx.deployment_active` | 1 if deployment within last 30 min on entity or direct dependency |
| `ctx.maintenance_active` | 1 if inside maintenance window |
| `ctx.business_hours` | 1 if within entity's business calendar |
| `ctx.tier`, `ctx.criticality` | CMDB tier (1–4) and criticality (1–5) |
## 5.6 Behavioural
| Feature | Definition |
|---|---|
| `beh.z_individual[f]` | (x_f − μ_individual,f,context) / max(σ_individual,f,context, ε) for each curated feature f |
| `beh.z_peer[f]` | Same against peer-group statistics |
| `beh.wow_pct[f]` | % change vs. same window one week earlier |
| `beh.auth_fail_ratio`, `beh.offhours_access` | Security entities (users, service accounts) |
`ε` = 1% of the population mean for the feature, to avoid division blow-up on flat series. Baseline statistics are read from broadcast state published by TS-06 (`ref.baselines`).
# 6. Feature Registry Definition
```
# features/vol.error_rate.yaml
name: vol.error_rate
category: volumetric
windows: [1m, 5m, 1h]
entity_classes: [cmdb_ci_service, cmdb_ci_api_gateway, cmdb_ci_db_instance]
input_filter: "event.outcome != null"
aggregation:
  type: ratio
  numerator:   "count(event.outcome == 'failure')"
  denominator: "count(*)"
  min_denominator: 20          # below this emit null + quality flag
dtype: float32
null_policy: carry_forward_1_window_then_null
curated_for_spc: true
pii: false
owner: ml-engineering
version: 2
```
# 7. Window Semantics
| Window | Type | Slide | Allowed lateness | Emit |
|---|---|---|---|---|
| 1m | Sliding | 15 s | 2 min | On watermark pass |
| 5m | Sliding | 1 min | 2 min | On watermark pass |
| 1h | Sliding | 5 min | 10 min | On watermark pass |
Late events within allowed lateness trigger a window update (upsert in online store, new version in offline store). Late events beyond lateness are counted (`feature_late_dropped_total`) and excluded.
# 8. Feature Vector Message (`features.vectors`)
```
record FeatureVector {
  string feature_vector_id;     // <entity_id>:<window>:<window_end_ms>
  string entity_id;
  string entity_class;
  string window;                // "1m" | "5m" | "1h"
  long   window_start_ms;
  long   window_end_ms;
  string registry_version;      // hash of feature registry used
  array<string> feature_names;  // dictionary-encoded per registry_version
  array<float>  values;         // NaN for null
  array<string> quality_flags;  // e.g. low_denominator, cmdb_stale, late_update
  string baseline_maturity;     // Bootstrap-0 | Bootstrap-1 | Bootstrap-2 | Mature
  map<string> context;          // deployment_active, maintenance_active, change_id
}
```
# 9. Online Store (Redis) Design
## 9.1 Key space
| Key pattern | Type | Content | TTL |
|---|---|---|---|
| `fv:{<entity_id>}:<window>:latest` | Hash | name→value for latest vector + window_end | 2 × window (min 2 h for 1h) |
| `fv:{<entity_id>}:<window>:seq` | Stream (XADD, MAXLEN ~) | Sequence of last N vectors (1m: 120, 5m: 288) for LSTM / Transformer | 24 h |
| `bd:{<entity_id>}:<window>` | Hash | Baseline deltas (`beh.z_*`) | 2 × window |
| `gr:{<entity_id>}:edges` | Hash | dst_entity → packed(calls, err_ratio, p95) for last 5m | 10 min |
| `ctx:{<entity_id>}` | Hash | Context flags | 1 h |
| `hist:{<entity_id>}:1d` | Sorted set | Daily summaries for 30 days | 30 d |
Curly braces form the hash tag so all keys for an entity share a slot.
## 9.2 Cluster configuration
| Parameter | Value |
|---|---|
| Nodes | 6 primaries + 6 replicas baseline (3 AZs); scale to 18 primaries |
| Node size | 8 vCPU, 32 GiB, `maxmemory` 24 GiB |
| `maxmemory-policy` | `volatile-ttl` (all keys carry TTLs) |
| Persistence | AOF `everysec` on replicas only; RDB nightly snapshot |
| Client | Cluster-aware, pipelining, connection pool 64/instance, read-from-replica for sequences |
| Sizing rule | ≈ 6 KiB per entity per window (latest + deltas) + 0.8 KiB × sequence length; 200k entities ≈ 160 GiB primary memory incl. overhead |
# 10. Serving API
```
service FeatureService {
  rpc GetVectors(GetVectorsRequest) returns (GetVectorsResponse);
  rpc GetSequence(GetSequenceRequest) returns (GetSequenceResponse);
  rpc GetGraphSnapshot(GetGraphRequest) returns (GraphSnapshot);
}
message GetVectorsRequest { repeated string entity_ids = 1; string window = 2; repeated string features = 3; bool include_deltas = 4; }
message GetSequenceRequest { string entity_id = 1; string window = 2; int32 length = 3; }   // max 288
message GetGraphRequest { repeated string seed_entities = 1; int32 hops = 2; }            // max hops 2
// Errors: NOT_FOUND (no vector), FAILED_PRECONDITION (registry_version mismatch), DEADLINE_EXCEEDED (default 20 ms)
```
Callers: ML inference (TS-05), Diagnostic agent (TS-15, read-only). Rate limits per caller identity are enforced at the service.
# 11. Offline Store and Training Materialisation
| Table | Partitioning | Contents | Retention |
|---|---|---|---|
| `features_5m` (Iceberg) | day(window_end), bucket(64, entity_id) | All 5m vectors | 24 months |
| `features_1h` | day(window_end) | All 1h vectors | 24 months |
| `detections` | day(ts) | `ml.detections` copy | 24 months |
| `labels` | day(label_ts) | `feedback.labels` resolved to (entity_id, time range, label) | 24 months |
Training sets are built with a point-in-time join: a label applies to vectors for its entity whose `window_end` lies inside `[anomaly_start − 30 min, anomaly_end]`; vectors outside any label are treated as unlabelled (not negative) except where an analyst false-positive label exists. Every training set is identified by an Iceberg snapshot id recorded in the Model Registry (TS-06).
# 12. Failure Modes
| Failure | Handling |
|---|---|
| Redis primary loss | Replica promoted (< 15 s); inference uses last vector from Kafka-backed local cache (60 s) |
| Redis memory > 75% | HPA scale-out and slot migration (TS-12); TTL eviction protects against OOM |
| Registry version mismatch between job and inference | Inference rejects vector (`FAILED_PRECONDITION`); deployment pipeline blocks mixed versions beyond 10 min |
| Baseline broadcast stale | Deltas computed on last baseline; flag `baseline_stale`; TS-06 alert |
| Offline write failure | Retry via `cg-offline-sink`; backfill from `features.vectors` (24 h retention) or replay of `raw.*` (72 h) |

# 14. Security Controls
| ID | Control |
|---|---|
| TS04-SEC-001 | Redis ACL users per caller; TLS in transit; no `KEYS`/`FLUSHALL` for application users |
| TS04-SEC-002 | Offline store encrypted with KMS; access via training service account only; analyst access to aggregated views |
| TS04-SEC-003 | Features never contain raw PII; registry `pii: true` features are rejected by CI |
# 15. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS04-AC-001 | Reconciliation of 24 h of stream vs. batch recomputation: parity within NFR-005 |
| TS04-AC-002 | Load test at 200k entities: read P99 ≤ 5 ms single, ≤ 10 ms batch of 100 |
| TS04-AC-003 | Point-in-time join reproduces identical training set from the same snapshot id twice |
| TS04-AC-004 | Primary node kill causes no inference errors beyond 60 s cache window |
