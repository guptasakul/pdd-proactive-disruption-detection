# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
Defines the platform every agent runs on and the Orchestrator agent (Agent 06) that coordinates them. Specialist agent behaviour is in TS-15; safety tiers, guardrails and overrides are in TS-16 and are enforced by the tool execution layer defined here.
# 2. Component Decomposition
| Sub-component | Responsibility |
|---|---|
| Agent runtime SDK | ReAct loop, prompt/response handling via LLM gateway, step budget, reflection, structured logging |
| Tool execution layer (TEL) | The only path from agents to external systems: capability check, tier enforcement, guardrails, rate limits, locks, audit |
| Tool registry | Versioned tool definitions with schema, tier, scope, rollback reference |
| Incident State Object (ISO) store | Redis (primary) with PostgreSQL write-behind for durability |
| Task bus | Kafka topics `agents.tasks` / `agents.results` / `agents.escalations` |
| Orchestrator agent | Decomposition, dispatch, monitoring, locking, escalation, SLA, closure |
| Memory services | Working (ISO), episodic (per-agent), semantic (RAG from TS-13) |
| Human handover service | Builds and delivers handover briefs; receives human task completion |
# 3. Key Design Decisions
| Decision | Rationale |
|---|---|
| Guardrails live in TEL, not prompts | LLM reasoning cannot override hard constraints |
| Shared ISO rather than agent-to-agent chat | Single source of truth; any agent or human can read state; auditable |
| Orchestrator is the only agent with full visibility | Narrow specialists reduce reasoning error and side-effects |
| Deterministic workflow skeleton with LLM reasoning inside steps | Predictable ordering for safety-critical sequencing (diagnosis before remediation) |
| Distributed lock per service for remediation | Prevents conflicting concurrent changes |
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS14-NFR-001 | Orchestrator dispatch of first tasks ≤ 5 s after incident `create` |
| TS14-NFR-002 | ISO read/write P99 ≤ 10 ms; durable copy ≤ 2 s behind |
| TS14-NFR-003 | Kill switch halts new actions in scope ≤ 5 s (TS-16) |
| TS14-NFR-004 | 100% of tool calls audited with reasoning trace |
# PART B — LOW-LEVEL SPECIFICATION
# 5. ReAct Loop Specification
```
run(agent, objective, iso_ref):
    budget = agent.profile.max_steps            # e.g. Triage 8, Diagnostic 15, Remediation 10 (≤ 5 actions)
    for step in 1..budget:
        state  = iso.read(iso_ref, view=agent.profile.iso_view)
        think  = llm.generate(function=agent.reasoner, inputs={objective, state, tool_catalog(agent), history})
                 # output schema: {thought, next_action: {tool, params} | null, done: bool, confidence}
        audit.log(step, think)                  # reasoning trace verbatim
        if think.done: break
        if think.confidence < agent.profile.min_confidence: escalate("low_confidence"); return
        result = TEL.execute(agent.identity, think.next_action, iso_ref)     # enforces tiers, guardrails
        iso.append(iso_ref, observation(step, think.next_action, result))
        if result.status in {denied, guardrail_block}: escalate(result.reason); return
        if result.status == failed and retries_exhausted(think.next_action): escalate("tool_failure"); return
    reflection = llm.generate(function=agent.reflector, inputs={objective, iso_delta})
        # {outcome: met|partial|not_met, summary, recommended_next}
    iso.write(iso_ref, agent_summary=reflection)
    publish agents.results {agent, outcome, summary}
    if reflection.outcome != met: escalate("objective_not_met", reflection)
```
Reasoner calls use temperature 0.1, function-calling/structured output, and only tools in the agent's capability profile are offered in `tool_catalog`.
# 6. Incident State Object (ISO)
## 6.1 Schema (abridged)
```
{
  "iso_version": 1, "incident_id": "...", "itsm_refs": {"servicenow": "INC0091234", "pagerduty": "Q1ABC..."},
  "severity": "P2", "status": "investigating",        // new|triaged|investigating|remediating|monitoring|resolved|closed
  "lifecycle": [{ "ts": "...", "from": "new", "to": "triaged", "by": "triage-agent" }],
  "payload_ref": "decision.incidents offset/partition",
  "entities": [...], "blast_radius": [...],
  "triage":     { "narrative": "...", "severity_confidence": 0.84, "duplicates": [] },
  "diagnosis":  { "hypotheses": [...], "artefacts": [...], "evidence_confidence": 0.77 },
  "comms":      { "sent": [{ "channel": "slack", "ts": "...", "type": "bridge_update" }], "acks": [...] },
  "remediation":{ "plan": [...], "actions": [{ "action_id": "...", "tool": "...", "tier": 2, "status": "done" }],
                  "lock": { "service": "payments-api", "holder": "remediation-agent#3", "expires": "..." } },
  "tasks":      [{ "task_id": "...", "agent": "diagnostic", "status": "running", "deadline": "...", "depends_on": [] }],
  "escalations":[{ "ts": "...", "reason": "low_confidence", "to": "oncall:payments", "brief_ref": "..." }],
  "human_overrides": [...],
  "version": 42                                         // optimistic concurrency
}
```
## 6.2 Access rules
| Agent | Read view | Write sections |
|---|---|---|
| Orchestrator | Full | `status`, `lifecycle`, `tasks`, `escalations`, `remediation.lock` |
| Triage | Payload, entities | `triage`, `itsm_refs` |
| Diagnostic | Payload, triage | `diagnosis`, `blast_radius` |
| Comms | Triage, diagnosis summary, status | `comms` |
| Remediation | Diagnosis, blast radius, lock | `remediation.plan`, `remediation.actions` |
| Learning | Full (read-only after resolution) | None (writes to knowledge base and labels) |
Writes use compare-and-set on `version`; conflicts retried up to 3 times with re-read. Redis key TTL = incident SLA + 24 h; PostgreSQL copy retained per audit retention.
# 7. Tool Execution Layer
## 7.1 Tool definition
```
tool: k8s.restart_deployment
version: 1.2.0
category: cloud_infrastructure
tier: 2
scope_param: namespace/deployment       # mapped to service via CMDB for scope checks
params_schema: { namespace: string, deployment: string, reason: string }
preconditions: [ "deployment.replicas >= 2", "no active rollout" ]
rollback_ref: k8s.rollout_undo           # required for tier ≥ 2 (irreversibility gate)
blast_radius_fn: dependency_downstream(service, depth=1)
rate_limit: { per_incident: 2, per_hour_global: 20 }
egress: [ "https://k8s-api.prod-cluster.internal" ]
allowed_agents: [ remediation ]
```
## 7.2 Execution pipeline
| # | Check | On failure |
|---|---|---|
| 1 | Agent identity valid; tool in agent's capability profile | `denied` |
| 2 | Params valid against schema | `invalid` |
| 3 | Kill switch / agent paused for scope | `denied:paused` |
| 4 | Production lock (change freeze, major-incident window) for tier ≥ 2 | `denied:freeze` |
| 5 | Scope: target service within agent's declared scope, else Orchestrator approval | `pending_cross_scope` |
| 6 | Rate limits (agent, tool, incident) | Circuit breaker trips; agent paused; human alerted |
| 7 | Irreversibility gate: tier ≥ 2 and no `rollback_ref` → reclassify Tier 4 | `handoff_human` |
| 8 | Blast-radius cap: radius > current service + direct deps → escalate to Tier 3 | `pending_approval` |
| 9 | Tier policy: Tier 1/2 execute; Tier 3 request approval (10-min timeout → escalate); Tier 4 never execute, hand off | per tier |
| 10 | Lock: remediation tools acquire service lock | `denied:locked` |
| 11 | Execute with timeout; capture raw response | `failed` with error |
| 12 | Audit record (TS-16 §7) written before returning | — |
| 13 | Tier 2 notify on-call; post-action health watch registered | — |
## 7.3 Remediation lock
Redis `SET lock:svc:{service} <holder> NX PX 900000`, renewed every 60 s by holder; released on action completion; Orchestrator can force-release on holder failure after TTL. Lock acquisition and release audited.
# 8. Memory Tiers
| Tier | Store | Content | Retention |
|---|---|---|---|
| Working | ISO (Redis) | Current incident state, tool history, reasoning trace pointers | SLA + 24 h (durable copy per audit) |
| Episodic | PostgreSQL `agent_episodes` | Per agent: last 500 incidents — situation signature, actions, outcome, reviewer verdict | Rolling 500 per agent |
| Semantic | RAG knowledge base (TS-13) | Incidents, runbooks, known errors, directory, dependencies | Per source |
Episodic memory use: before acting, the agent retrieves the 3 most similar past episodes (signature similarity) and includes their outcomes in the Think context; actions with recent failed outcomes on similar signatures lower the agent's confidence by 0.1 each.
# 9. Orchestrator Agent (Agent 06)
## 9.1 Workflow templates
| Severity | Step graph (→ sequential, ‖ parallel) |
|---|---|
| P1 | Triage → (Diagnostic ‖ Comms[initial page + exec summary]) → Remediation (gated) → Comms[updates every 15 min] → Learning |
| P2 | Triage → (Diagnostic ‖ Comms[page]) → Remediation (gated) → Comms[updates every 30 min] → Learning |
| P3 | Triage → Diagnostic → Comms[secondary channel] → Remediation (Tier 1–2 only unless approved) → Learning |
| P4 | Triage → Diagnostic (light: 30-min lookback) → Comms[ticket note only] → Learning |
## 9.2 Dispatch and monitoring
```
on decision.incidents(create):
    iso = create_iso(incident)
    plan = template[severity].instantiate(iso)     # tasks with depends_on and deadlines
    for task in plan.ready(): publish agents.tasks(task)
on agents.results(r):
    mark task done; for t in plan.newly_ready(): publish agents.tasks(t)
every 15 s:
    for task running past deadline (Triage 60 s, Diagnostic 5 min, Comms 60 s, Remediation 15 min):
        if attempts < 2: re-dispatch to another replica
        else: escalate(task, reason="stalled")
    check SLA timers: if ack/resolve within 20% of breach → escalate early
    check scope: if new entities/services join beyond initial classification → escalate("scope_expansion")
on decision.incidents(update|escalate): re-plan (e.g. P3→P2 adds Comms paging, tighter deadlines)
```
## 9.3 Escalation triggers
| Trigger | Condition |
|---|---|
| Action limit | Any agent hits its step budget or action limit |
| Confidence floor | Agent confidence < profile floor (default 0.70; raised in Phase 2–3) |
| Unexpected tool response | Schema mismatch, unknown error class |
| Scope expansion | Incident spans new service clusters or severity rises 2 levels |
| SLA risk | Within 20% of ack/resolve breach |
| Guardrail trip | Any TS-16 guardrail block |
## 9.4 Human handover brief (schema)
| Field | Content |
|---|---|
| `situation` | 3-sentence current state |
| `timeline` | Key events and agent actions with timestamps |
| `actions_taken` | Each action with tier, outcome and rollback availability |
| `outstanding_tasks` | Tasks not completed and why |
| `hypotheses` | Current ranked root causes with confidence |
| `recommended_next_steps` | 1–3 steps with expected effect |
| `contacts` | Service owners, on-call, SMEs |
| `links` | ITSM, dashboards, runbooks, audit trail |
Delivered as ITSM work note + chat message to on-call; human acceptance recorded in ISO (`human_overrides`).
## 9.5 Closure
1. All tasks complete or explicitly cancelled by human.
2. ITSM state = resolved by human or by agent where policy allows (TS-08 OI-01).
3. Trigger Learning agent; wait for completion (max 30 min, non-blocking for closure).
4. Comms agent sends resolution notification.
5. Publish closure summary; release locks; ISO status → closed; schedule ISO purge from Redis.

# 11. Failure Modes
| Failure | Handling |
|---|---|
| Orchestrator replica failure | Leader election (K8s lease); new leader rebuilds plans from ISO and task bus |
| LLM gateway down | Agents run deterministic fallback paths (Triage enrichment without narrative; Comms templated messages); Diagnostic/Remediation escalate to human |
| ISO conflict storm | Backoff; Orchestrator serialises writes for the incident |
| Agent loops (same action repeated) | Duplicate-action detector: same tool+params twice in an incident → block and escalate |

# 13. Security Controls
| ID | Control |
|---|---|
| TS14-SEC-001 | Each agent type has its own workload identity; TEL authorises on identity, not on prompt content |
| TS14-SEC-002 | Tool credentials held by TEL, never exposed to agent processes or LLM context |
| TS14-SEC-003 | Agent egress only via TEL egress gateway with per-tool destination allow-lists |
| TS14-SEC-004 | Inputs from tickets, logs and notes sanitised and tagged as untrusted data before inclusion in prompts |
# 14. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS14-AC-001 | P1 synthetic incident: Triage dispatched ≤ 5 s; Diagnostic and Comms run in parallel; Remediation waits for Diagnostic |
| TS14-AC-002 | Tool outside capability profile is denied 100% and audited |
| TS14-AC-003 | Two Remediation agents targeting the same service: only one acquires lock |
| TS14-AC-004 | Killing the Orchestrator leader mid-incident: workflow resumes ≤ 30 s without duplicate actions |
| TS14-AC-005 | Every tool call in a 200-incident replay has a matching audit record with reasoning trace |
