# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
Defines the controls that keep the solution trustworthy, auditable and compliant: who may approve models and rules, what evidence is kept, how personal data is minimised, how long records are retained, and how controls map to common frameworks. Agent-specific action governance is in TS-16; this specification provides the shared audit store and governance bodies that TS-16 relies on.
# 2. Governance Bodies and Roles
| Body / role | Responsibility | Cadence |
|---|---|---|
| ML Governance Committee | Approve major model versions; review bias, drift and performance reports; own model risk register | Monthly + ad hoc |
| Change Advisory Board (CAB) | Approve major model versions, policy changes affecting P1/P2 behaviour, agent tier reclassification | Per change calendar |
| Model owner (ML Engineering) | Model cards, evaluation, minor version peer review | Continuous |
| Policy owner (SRE Platform) | Severity, suppression and routing policies | Continuous |
| Data Protection Officer | Approve PII field lists, pseudonymisation and retention | Quarterly review |
| Internal audit | Independent review of audit trail completeness and control operation | Annual |
# 3. Key Design Decisions
| Decision | Rationale |
|---|---|
| Single append-only audit store for predictions, decisions, config changes and agent actions | One place to reconstruct "why did the system do that" |
| Explanations generated at prediction time, not reconstructed later | Explanations match the exact model and features used |
| Pseudonymise before training, not after | Training sets never contain direct identifiers |
| Compliance options as configuration profiles | Industry-neutral core; regulated profiles add residency, retention and evidence controls |
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS10-NFR-001 | Audit records immutable for retention period; tamper-evident (hash chain) |
| TS10-NFR-002 | Any prediction, decision or agent action retrievable with lineage in ≤ 60 s query time |
| TS10-NFR-003 | Monthly governance report generated automatically by day 3 of following month |
# PART B — LOW-LEVEL SPECIFICATION
# 5. Model Governance Controls
| Control ID | Area | Policy | Implementation | Evidence |
|---|---|---|---|---|
| GOV-MR-01 | Registry | No model served unless registered with version, lineage, metrics, approval and retirement date | Inference loader refuses unregistered/unsigned artefacts | Registry export; loader logs |
| GOV-MR-02 | Retirement | Models reviewed before retirement date; expired models cannot be promoted | Registry stage rule | Review minutes |
| GOV-EX-01 | Explainability | Every detection carries SHAP top-k and per-model contribution | TS-05 detection schema validation | Sample audit |
| GOV-EX-02 | Explanation fidelity | Quarterly check: removing top-3 SHAP features reduces score by ≥ 40% on average | Evaluation job | Report |
| GOV-BI-01 | Bias / blind spots | Detection recall and FP rate sliced by tier, region/site, entity class, time-of-day, business vs. off hours | Evaluation slices (TS-06 §8.2) | Monthly report |
| GOV-BI-02 | Slice tolerance | No slice recall < 0.8 × overall recall without documented exception | Promotion gate | Gate log |
| GOV-CC-01 | Change control | Major model versions: CAB + ML Governance approval; minor: peer review + automated gate | Registry approval fields | Change records |
| GOV-CC-02 | Policy changes | Severity/suppression/routing changes via Git PR with two approvers incl. policy owner | Branch protection | PR history |
| GOV-AU-01 | Audit trail | All predictions (TP and FP) retained ≥ 12 months with traceability to feature values | Audit store + offline features | Retrieval test |
# 6. Audit Store
## 6.1 Record types
| `record_type` | Producer | Key content |
|---|---|---|
| `prediction` | TS-05 | detection_id, model versions, scores, top features with values, feature_vector_id |
| `decision` | TS-07 | candidate_id, filters evaluated, severity inputs and rule, outcome |
| `itsm_operation` | TS-08 | platform, operation, external_ref, result |
| `label` | TS-08 | feedback label, actor (pseudonymised) |
| `config_change` | GitOps (TS-11) | commit, diff summary, approver, apply result |
| `model_lifecycle` | TS-06 | stage transition, gate metrics, approver |
| `threshold_change` | TS-11 | parameter, old, new, trigger, cumulative drift |
| `agent_action` | TS-14/16 | Full audit fields per TS-16 §7 |
| `access` | Platform | Privileged human access events |
## 6.2 Storage and integrity
| Item | Specification |
|---|---|
| Ingest | `audit.trail` topic → audit sink (exactly-once) |
| Primary store | OpenSearch index with write-once ILM policy (no update/delete API for any role); daily indices |
| Archive | Object storage with object lock (compliance mode) for full retention period |
| Tamper evidence | Per-index hourly hash chain: H_n = SHA-256(H_{n−1} ‖ SHA-256(records in hour n)); chain anchors written to a separate account/bucket |
| Access | `auditor` role read-only; agents and services have no read or delete rights on audit indices |
## 6.3 Retention schedule
| Data | Default retention | Configurable range |
|---|---|---|
| Raw telemetry topics | 72 h | 24 h–14 d |
| Hot logs (OpenSearch) | 7 d hot, 30 d warm, 90 d cold, delete at 12 months | per profile |
| Metrics (VictoriaMetrics) | 13 months infra; 6 months high-cardinality app | per profile |
| Feature training data | 24 months | 12–60 months |
| Predictions and decisions audit | ≥ 12 months | 12 months–7 years |
| Agent action audit | ≥ 24 months | 24 months–7 years |
| Model artefacts | Indefinite (registry) | — |
| Audit logs (platform/access) | 5 years | 1–10 years |
# 7. Data Privacy Controls
| Control ID | Control | Implementation |
|---|---|---|
| PRIV-01 | Data minimisation | Source descriptors declare fields; unmapped fields dropped at normalisation unless whitelisted |
| PRIV-02 | Pseudonymisation | HMAC-SHA256 with KMS keys, rotated 90 days (TS-03 §8.7) |
| PRIV-03 | Re-identification | Only `dpo-approved` role via break-glass workflow with ticket reference; logged |
| PRIV-04 | LLM prompt redaction | Pre-prompt redaction of emails, phone numbers, card-like numbers, national-ID patterns, secrets/tokens (TS-13) |
| PRIV-05 | Right to erasure | Pseudonym key destruction for a subject renders training data non-attributable; erasure log maintained |
| PRIV-06 | Automated decisions | The system makes operational decisions only; no decisions with legal or similarly significant effect on natural persons (GDPR Art. 22 not triggered). Security detections about users are advisory and require human review before any action affecting a person |
| PRIV-07 | Data residency | Per-region processing; cross-region flow limited to detections/incidents; profile can forbid cross-region entirely |
# 8. Compliance Control Mapping
| Framework | Criterion / article | Solution controls |
|---|---|---|
| SOC 2 — CC6 (Logical access) | Access restricted and reviewed | TS09-SEC-003/004, quarterly access review |
| SOC 2 — CC7 (System operations) | Monitoring, incident response | Self-monitoring (TS-11), ITSM integration (TS-08) |
| SOC 2 — CC8 (Change management) | Authorised, tested changes | GOV-CC-01/02, GitOps (TS-11) |
| SOC 2 — A1 (Availability) | Capacity, backup, recovery | TS-09 HA/DR, TS-12 scaling, backup tests |
| GDPR Art. 5 / 25 | Minimisation, privacy by design | PRIV-01, PRIV-02, PRIV-04 |
| GDPR Art. 22 | Automated individual decisions | PRIV-06 |
| GDPR Art. 30 | Records of processing | Source descriptor catalogue + retention schedule |
| ISO/IEC 42001 (AI management) | AI risk, lifecycle, transparency | Model governance §5, model cards, TS-16 |
| NIST AI RMF | Govern / Map / Measure / Manage | Committee, risk register, metrics, rollback |
# 9. Regulated-Industry Configuration Profiles
| Profile option | Effect |
|---|---|
| `residency.strict` | No cross-region data flow; LLM must be in-region or self-hosted |
| `retention.extended` | Audit retention 7–10 years; archive in WORM storage |
| `llm.self_hosted_only` | Disables external LLM endpoints (TS-13) |
| `agents.max_tier` | Caps autonomous tier (e.g. Tier 1 only) regardless of phase |
| `evidence.export` | Monthly signed evidence pack (control status, sampled audit records, model reports) for regulators/auditors |
| `incident.regulatory_reporting` | Adds regulatory notification timers and templates to P1 workflow (content human-approved) |

# 11. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS10-AC-001 | Random sample of 100 detections fully reconstructed (features, model versions, decision, ITSM outcome) from audit in ≤ 60 s each |
| TS10-AC-002 | Attempted update/delete on audit indices by any non-system role fails and is itself audited |
| TS10-AC-003 | Hash-chain verification detects a deliberately altered record in test environment |
| TS10-AC-004 | PII scan of training data and LLM prompt logs finds zero unredacted direct identifiers |
| TS10-AC-005 | Monthly governance report generated with all sections populated |
