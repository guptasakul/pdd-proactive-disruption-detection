# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
Self-management keeps the solution healthy and configured as declared. Self-correction improves the quality of the solution's output from feedback, within hard bounds and human review gates. This specification also instruments the Key Risk Indicators (KRIs) that warn of degradation before KPIs move. Model retraining mechanics are in TS-06; this spec defines the triggers and feedback paths into it.
# 2. Self-Management Domains
| Domain | Monitored | Autonomous action | Human gate |
|---|---|---|---|
| Component health | Liveness/readiness, consumer lag, checkpoint latency, Redis memory, inference queue | Pod restart, Flink restart from checkpoint, DLQ replay | None |
| Configuration drift | Live cluster vs. Git desired state | Argo CD auto-sync of non-destructive diffs | Destructive changes (deletions) |
| Model lifecycle | Hourly F1/precision/recall; daily PSI/KS | Retrain, shadow, promote, rollback (TS-06) | Major versions |
| Pipeline throughput | End-to-end latency, lag, checkpoint duration, store write latency | Parallelism and partition rebalancing (TS-12) | Scaling beyond max bounds |
| Data quality | Schema failure, null, duplicate and skew rates per source | Quarantine, rate-limit, alert owners | Source disablement |
| Dependency availability | ITSM, TI feeds, CMDB, IdP, LLM | Circuit breakers, cached fallback, queued replay | None |
# 3. Self-Correction Loops
| Loop | Signal | Immediate correction | Longer-term learning | Bound / gate |
|---|---|---|---|---|
| L-FP | Analyst marks false positive | Negative label; draft suppression rule if pattern ≥ 3 | Retrain; temporary weight reduction for triggering model | Rule activation needs approval |
| L-SEV-DOWN | Severity downgraded | Severity threshold for pattern nudged down-sensitivity | Monthly severity calibration | ±0.05 per cycle; ±0.15 cumulative |
| L-SEV-UP | Severity upgraded | Pattern flagged under-scored; tighten | Sensitivity increased on retrain | Same bounds |
| L-RC-OK | Root cause confirmed | Reinforce precursor pattern in Transformer training set | Strengthen runbook association | — |
| L-RC-FIX | Root cause corrected | Negative example for wrong hypothesis | Correlation weights updated | — |
| L-NOTES | Resolution notes | NLP extracts steps; runbook gap detection | Runbook proposals queued | Human review of runbooks |
# 4. Key Design Decisions
| Decision | Rationale |
|---|---|
| All self-corrections are bounded per cycle and cumulatively | Prevents runaway sensitivity changes from noisy feedback |
| Human review gate at ±0.15 cumulative drift from last reviewed baseline | Keeps humans in charge of policy direction |
| Suppression rules always proposed, never self-activated | A wrong suppression silently hides real incidents |
| Self-monitoring has an external dead-man's-switch | The system cannot be the only witness to its own failure |
# 5. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS11-NFR-001 | Drift between Git and cluster reconciled ≤ 3 min (polling) or ≤ 30 s (webhook) |
| TS11-NFR-002 | Feedback label → effect on suppression proposal ≤ 15 min; → training label next daily cycle |
| TS11-NFR-003 | KRIs evaluated at least every 1 min (streaming KRIs) or daily (batch KRIs) |
# PART B — LOW-LEVEL SPECIFICATION
# 6. Health Probes Contract
| Endpoint | Semantics | Failure action |
|---|---|---|
| `GET /healthz` | 200 only if process functional: event loop responsive, no deadlock watchdog trip, error-loop counter < limit | Restart after 3 failures (period 10 s) |
| `GET /readyz` | 200 only if dependencies reachable and models/config loaded; 503 during model reload or checkpoint restore | Removed from load balancing |
| `GET /metrics` | Prometheus metrics | — |
| Heartbeat event | Each pipeline stage publishes `heartbeat` on `control.heartbeat` every 30 s | External dead-man's-switch pages if absent 5 min |
Watchdog: each service runs an internal watchdog thread that fails `/healthz` if the main processing loop has not advanced for > 60 s while input is available.
# 7. GitOps Drift Correction
```
loop every 3 min (and on Git webhook):
    desired = render(git@main, environment overlay)
    live    = kubernetes.get(managed resources)
    diff    = structural_diff(desired, live)          # ignoring status and server-managed fields
    log diff to audit (record_type=config_change, kind=drift_detected)
    for change in diff:
        if change.kind in {create, update}: apply(change)          # auto
        if change.kind == delete: queue_for_approval(change)        # destructive gate
    post-sync: wait for health (timeout 10 min); on failure alert platform team and keep last healthy revision
```
Argo CD settings: `syncPolicy.automated.prune=false`, `selfHeal=true`, sync windows aligned to change freezes (TS-16 production lock).
# 8. KRI Instrumentation
| KRI | Computation | Threshold | Autonomous response | Escalation |
|---|---|---|---|---|
| Model distribution drift | Daily PSI per key feature (TS-06) | > 0.2 | Retraining signal | ML Eng alert |
| Pipeline end-to-end latency | P99 (now − event `@timestamp`) at inference input, 1-min histogram | > 30 s for 5 min | Scale Flink; rebalance partitions | Platform P2 if > 15 min |
| Kafka consumer lag | Max per partition per group | > 50,000 events | HPA scale; Cruise Control | Platform P2 if growing 15 min |
| Schema validation failure rate | DLQ / total per source, 15-min window | > 2% | Quarantine; source rate-limit if > 20% | Data Eng + source owner |
| FP suppression rule coverage | Rules with < 3 fires in 30 d | Any | Flag for review; archive at 90 d unused | Policy owner weekly |
| Feature Store availability | Read P99 and success ratio | > 10 ms or < 99.9% | Redis scale-out / slot migration | Platform P2 |
| Autonomous threshold drift | Σ applied deltas since last human-reviewed baseline, per threshold | \|Σ\| > 0.15 | Pause recalibration; open review | Policy owner |
| ITSM integration health | Consecutive API failures per platform | > 3 | Circuit breaker; queue for replay | Platform P2 |
KRIs are computed by a `kri-evaluator` service reading VictoriaMetrics and the audit store, published as `kri_status{kri, state}` (ok/warn/breach), and reported weekly (TS-10 §10).
# 9. Feedback Processing
## 9.1 Label routing
```
on FeedbackLabel l from feedback.labels:
    write l to offline labels table (TS-04 §11)
    switch l.label_type:
      false_positive:      fp_pattern_miner.add(l); model_weight_adjuster.penalise(l)
      severity_adjustment: severity_calibrator.add(delta = rank(to) - rank(from), pattern = signature(l))
      root_cause_*:        rc_feedback.add(l)           # correlation weights, M4 training set
      resolution_notes:    nlp_queue.add(l)             # TS-13 function F6 / Learning agent
    audit(record_type=label_processed)
```
## 9.2 Detection signature
A signature groups similar detections for pattern mining: `(entity_class, service, predicted_mode, top-3 SHAP feature names (sorted), hour bucket (4 h), deployment_flag)`.
## 9.3 Temporary model weight penalty
On a confirmed false positive, models whose contribution to that detection was > 30% have their fusion weight for the (domain, signature) multiplied by 0.9, floor 0.5 of original, decaying back to 1.0 over 7 days unless further FPs occur. Penalties are logged as `threshold_change` records.
# 10. Autonomous Threshold Recalibration
## 10.1 Triggers (rolling 7-day window per policy scope)
| Condition | Action |
|---|---|
| Auto-ticket FP rate > 5% | Tightening review: raise relevant severity/emit thresholds |
| Missed-incident rate > 10% (incidents raised by humans/users with no prior detection ≥ P3) | Relaxation review: lower thresholds |
## 10.2 Algorithm
```
for each threshold θ in scope (e.g. severity.p3, fusion.emit_threshold per class):
    proposed = optimise θ on last 7 d labelled data to minimise cost = FN_cost*FN + FP_cost*FP   # FN_cost=5, FP_cost=1 default
    delta = clamp(proposed − θ, −0.05, +0.05)                                                     # per-cycle bound
    if |cumulative_delta[θ] + delta| > 0.15:
         freeze(θ); open_review(θ, evidence); continue                                            # human gate
    apply θ += delta via Git commit by service identity (PR auto-merged for within-bounds changes)
    cumulative_delta[θ] += delta ; audit(threshold_change)
cycle frequency: daily at 04:00 UTC; max one change per threshold per day
```
After human review, the reviewed value becomes the new baseline and `cumulative_delta` resets to 0.
# 11. Suppression Rule Lifecycle
| Stage | Rule | System behaviour |
|---|---|---|
| Proposed | ≥ 3 FPs share a signature within 14 days | Draft rule generated with narrowest matching predicates; notify policy owner with evidence |
| Conflict check | New rule overlaps an active rule or would have suppressed any TP in last 30 d | Both surfaced with conflict highlighted; proposal blocked until resolved |
| Active | Approved by operator | Effective immediately via GitOps; every suppression logged |
| Review | Weekly | Flag if < 3 fires in 30 d or if it suppressed an event later labelled TP |
| Archived | No fire in 90 d, or overridden by analyst > 2 times in 30 d, or expiry | Moved to archive; searchable in audit |
Default expiry of every rule: 90 days after activation unless renewed.
# 12. Data-Quality Self-Correction
| Condition | Action |
|---|---|
| Source schema failures > 2% | DLQ quarantine; mapping-regression rollback if correlated with mapping deploy |
| Source null-field rate on required feature inputs > 20% | Feature marked degraded for source; models lower confidence |
| Duplicate ratio > 30% | Alert: double collection; dedup continues |
| Clock skew > 5 s median | Skew correction applied (TS-03 §8.2); owner alerted |

|---|---|

# 15. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS11-AC-001 | Manual `kubectl edit` of a managed Deployment is reverted within 3 min and audited |
| TS11-AC-002 | Injected deadlock in a service fails `/healthz` and the pod is restarted within 90 s |
| TS11-AC-003 | 3 synthetic FPs with identical signature produce one proposed rule with evidence; rule not active until approved |
| TS11-AC-004 | Recalibration never moves a threshold > 0.05 in a cycle; at cumulative 0.15 the review gate opens and changes stop |
| TS11-AC-005 | Each KRI breach in a fault-injection run triggers its documented autonomous response |
| TS11-AC-006 | Stopping all heartbeats triggers external dead-man's-switch page within 6 min |
