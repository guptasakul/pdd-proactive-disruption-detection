# PART A — DESIGN-LEVEL SPECIFICATION
# 1. Purpose and Scope
Layer 1 collects logs, metrics, traces and events from production infrastructure and applications and delivers them to the `raw.<domain>` Kafka topics with minimal transformation. It is responsible for completeness, durability at the edge and source identification. It is not responsible for normalisation, entity resolution or feature computation (TS-03, TS-04).
# 2. Source Catalogue
The catalogue is the authoritative list of sources. Each source has a `source_type` code used throughout the pipeline. Priority indicates Phase 1 onboarding order (the "top 5" sources in TS-17 are those marked P1).

# 3. Collector Topology
| Tier | Deployment | Responsibility |
|---|---|---|
| Agent | DaemonSet on every K8s node; systemd service on bare-metal/VMs | Local receive (OTLP, filelog, hostmetrics, kubeletstats); add resource attributes; batch; forward to gateway |
| Gateway | Deployment (≥ 3 replicas per AZ) behind internal LB | Network-device receivers (syslog, netflow, BMP), API pullers, tail sampling for traces, routing to `raw.<domain>`, disk-backed queue |
| Puller | CronJob / long-running Deployment | Batch/API sources (vulnerability, threat intel, cloud audit, business KPIs) |
Design decisions:
- **OpenTelemetry Collector (contrib) is the only mandated collector.** Existing vendor agents are permitted where they can export OTLP; they are then treated as sources, not collectors.
- **Two-tier agent/gateway** keeps per-node footprint within 1 vCPU / 512 MiB and centralises Kafka credentials in the gateway tier.
- **Traces are tail-sampled at the gateway**, retaining 100% of error and slow traces and a 10% baseline sample, because full trace volume is not needed for feature extraction and dominates bandwidth.
- **Logs and metrics are not sampled.** Volume control is by per-source rate limiting (TS-03), never silent sampling.
# 4. Non-Functional Requirements
| ID | Requirement |
|---|---|
| TS02-NFR-001 | Agent resource ceiling: 1 vCPU, 512 MiB per node at P95 load (limits enforced) |
| TS02-NFR-002 | Edge durability: gateway disk queue ≥ 2 h of baseline source volume per replica |
| TS02-NFR-003 | Collection latency: source emission to `raw.*` produce ≤ 5 s P99 for streaming sources |
| TS02-NFR-004 | Clock discipline: all hosts NTP/PTP-synchronised to ≤ 100 ms skew; skew measured and exported |
| TS02-NFR-005 | Coverage: ≥ 95% of production CIs in scope emit at least one signal type within 15 min (heartbeat) |
# PART B — LOW-LEVEL SPECIFICATION
# 5. Source Onboarding Contract
Every source is onboarded through a declarative descriptor stored in Git. The normaliser (TS-03) refuses events whose `source_id` has no approved descriptor.
```
# sources/app.apigw/payments-gw.yaml
source_id: app.apigw.payments-gw
source_type: app.apigw
domain: application
owner_team: payments-platform
cmdb_ci_hint: { field: "service.name", ci_class: "cmdb_ci_service" }
transport: { receiver: filelog, path: "/var/log/gw/access.json", format: json }
expected_volume_eps: { baseline: 4000, peak: 20000 }
rate_limit_eps: 30000                  # enforced at gateway
heartbeat: { max_silence: PT5M }
pii_fields: [ "client.ip", "user.id" ]  # pseudonymised in TS-03
ecs_mapping_ref: mappings/app.apigw/v3.yaml
retention_class: standard              # standard | security | audit
criticality: tier1
status: approved                       # draft | approved | retired
```
# 6. Collector Configuration (reference)
## 6.1 Agent pipeline
```
receivers:
  otlp: { protocols: { grpc: { endpoint: 0.0.0.0:4317 }, http: { endpoint: 0.0.0.0:4318 } } }
  filelog: { include: [/var/log/pods/*/*/*.log], start_at: end, operators: [ { type: container } ] }
  hostmetrics: { collection_interval: 15s, scrapers: { cpu: {}, memory: {}, disk: {}, network: {}, load: {}, filesystem: {} } }
  kubeletstats: { collection_interval: 15s, auth_type: serviceAccount }

  memory_limiter: { check_interval: 1s, limit_percentage: 80, spike_limit_percentage: 20 }
  resourcedetection: { detectors: [env, system, k8snode], timeout: 2s }
  k8sattributes: { extract: { metadata: [k8s.namespace.name, k8s.pod.name, k8s.deployment.name, k8s.node.name] } }
  attributes/source: { actions: [ { key: source.id, from_attribute: source_id, action: upsert } ] }
  batch: { send_batch_size: 2048, timeout: 2s }
exporters:
  otlp/gateway: { endpoint: otel-gateway.observability.svc:4317, tls: { ca_file: /etc/pki/ca.crt },
                  sending_queue: { enabled: true, storage: file_storage, queue_size: 50000 },
                  retry_on_failure: { initial_interval: 1s, max_interval: 30s, max_elapsed_time: 0 } }

```
## 6.2 Gateway routing
```
processors:
  routing:
    from_attribute: source.domain
    table:
      - { value: network,     exporters: [kafka/raw.network] }
```

# 7. Required Resource Attributes
Every record leaving Layer 1 MUST carry these attributes; records missing a required attribute are routed by TS-03 to the dead-letter topic.
| Attribute | Required | Description |
|---|---|---|
| `source.id` | Yes | Matches an approved onboarding descriptor |
| `source.domain` | Yes | network · security · application · database · platform · business |
| `source.type` | Yes | Catalogue code from Section 2 |
| `host.name` or `service.name` | Yes (one) | Primary hint for CMDB resolution |
| `deployment.environment` | Yes | prod · preprod · dev |
| `cloud.region` / `site` | Yes | Region or data-centre code |
| `observed_timestamp` | Yes | Collector receive time (UTC), used for skew computation |
| `k8s.*` | When applicable | Namespace, pod, deployment, node |
# 8. Source Health and Data-Quality Obligations
| Check | Where | Rule | Action |
|---|---|---|---|
| Heartbeat | Gateway + TS-03 | No events from a source for > `max_silence` | Emit `source_silent` event (P3 platform incident, tagged to source owner) |
| Volume anomaly | TS-03 | Volume outside [0.2×, 5×] of 7-day same-hour median | Emit `source_volume_anomaly`; SPC also scores it as a feature |
| Clock skew | TS-03 | \|event_ts − observed_ts\| > 5 s for > 1% of events in 5 min | Flag source; use observed_ts for windowing; alert owner |
| Rate limit breach | Gateway | Source exceeds `rate_limit_eps` | Excess queued then dropped with counter; owner alerted |
| Schema failure | TS-03 | > 2% rejection (KRI) | Dead-letter; alert data engineering |
# 9. Failure Modes
| Failure | Impact | Handling |
|---|---|---|
| Gateway unreachable from agents | Node telemetry delayed | Agent file-backed queue (50k batches); unlimited retry with backoff; `otelcol_exporter_queue_size` alert at 70% |
| Kafka unreachable from gateway | All telemetry delayed | Gateway disk queue (≥ 2 h); readiness flips to not-ready at 90% to shed new connections to healthy replicas |
| Agent OOM | Node telemetry lost until restart | `memory_limiter` refuses data before OOM; DaemonSet restarts; gap recorded as data-quality event |
| Network device syslog over UDP loss | Silent loss | Prefer TCP/TLS syslog; where UDP unavoidable, measure sequence gaps where vendor supports sequence numbers |
| API puller credential expiry | Source silent | Heartbeat rule; secrets rotated by secrets manager with 7-day pre-expiry alert |
# 10. Self-Observability
| Metric | Alert |
|---|---|
| `otelcol_receiver_accepted_*` / `refused_*` by source | Refused > 0.5% for 5 min |
| `otelcol_exporter_queue_size` / `queue_capacity` | > 70% for 10 min |
| `otelcol_exporter_send_failed_*` | > 0 sustained 5 min |
| `otelcol_process_memory_rss` | > 450 MiB on agent |
| `source_last_seen_seconds{source_id}` | > max_silence |
| `clock_skew_seconds{host}` | > 1 s P95 |
# 11. Security Controls
| ID | Control |
|---|---|
| TS02-SEC-001 | Agent → gateway and gateway → Kafka over mTLS; gateway holds the only Kafka producer credentials |
| TS02-SEC-002 | Agents run non-root with read-only root filesystem; host log paths mounted read-only |
| TS02-SEC-003 | Syslog from network devices received over TLS (RFC 5425) where supported; UDP receivers restricted to management VLAN by network policy |
| TS02-SEC-004 | API puller credentials scoped read-only and stored in the secrets manager |
| TS02-SEC-005 | Collector images signed and verified at admission (Sigstore/cosign policy) |
# 12. Acceptance Criteria
| ID | Criterion |
|---|---|
| TS02-AC-001 | All P1 sources onboarded with approved descriptors; events visible in `raw.*` with all required attributes |
| TS02-AC-002 | Kill Kafka for 60 min at baseline load: no event loss after recovery; gateway queues drain within 20 min |
| TS02-AC-003 | Agent P95 CPU ≤ 1 vCPU and RSS ≤ 512 MiB under 2× baseline node volume |
| TS02-AC-004 | Silencing a source triggers `source_silent` within `max_silence` + 1 min |
| TS02-AC-005 | Tail sampling retains 100% of error traces in a 1-hour injected-error test |
